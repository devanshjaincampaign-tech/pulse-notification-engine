UNDER THE HOOD

Small pieces. Clear guarantees.

The interface is a window into the backend — each visible action maps to a real API, persistence boundary, or delivery mechanism.

01⌑

Transactional outbox

Events land in PostgreSQL before the producer gets success. Workers claim rows safely, retry failures with backoff, and preserve exhausted events for investigation.

PostgreSQLSKIP LOCKEDAt-least-once
02⌁

Fan-out across instances

Each app instance subscribes to Redis Pub/Sub. The instance holding the recipient's socket delivers to its local user room — producers don't need to know where the user is connected.

Redis Pub/SubSocket.IO rooms
03◉

Identity with revocation

Short-lived access tokens are tied to persisted sessions. Refresh tokens are stored as hashes, rotated transactionally, and replay detection can revoke a session.

JWTRefresh rotationSessions
04↗

Persistence first, live second

Notifications are stored before live delivery. If a user is offline or a live message is missed, the REST feed and unread sync remain the recovery path.

REST feedUnread syncCursor paging
i
A note on delivery guarantees

WebSocket delivery is best effort; the notification feed is durable. Email is at-least-once — a retry after SMTP accepts a message may send a duplicate.
